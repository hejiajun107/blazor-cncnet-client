# M3.6 出生点映射 + 游戏信息面板 验收清单

> 范围：`/online/game` 房间页的地图预览出生点叠加 + 游戏信息面板。
> 涉及文件：`GameRoomService.cs`（`GetSpawnPointStates` / `SpawnPointState` 新增）、`GameLobby.razor`（出生点层 + `.map-info`）、`app.css`（`.spawn-*` / `.mi-*`）。
> 状态：实现完成，构建 0 错误。**出生点分配走已有 PO/OR 协议同步**（M3.5 已实现），本阶段补全可视化与点击交互。

---

## 0. 前置准备（必读）

- 单人可验证绝大部分功能（建房间 → 选地图 → 看出生点 → 点击分配）。
- 双客户端可验证「出生点占用与同步」：A 建房选图，B 加入后看同一张图上的出生点被 A 占用着色，B 改出生点 A 端同步更新。
- 需本地装有带 Waypoint 的地图（官方遭遇战地图基本都有）。

---

## 1. 出生点叠加展示（地图预览）

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 1.1 | 房主选中一张地图 | 预览图上方叠加出生点标记：青色编号圆点（1 起），位置与地图 Waypoint 对应 | ☐ |
| 1.2 | 出生点数量 | 标记数量 = min(地图 Waypoint 数, 房间最大人数)，不超过 8 | ☐ |
| 1.3 | 放大/缩小窗口（1280×720 ↔ 1920×1080） | 出生点始终贴合预览图对应位置（百分比定位，不变形） | ☐ |
| 1.4 | 悬浮出生点标记 | 显示提示：`出生点 N`；被占用时显示 `出生点 N · 玩家名` | ☐ |
| 1.5 | 未选地图时 | 预览区不显示出生点层（仅显示「请选择地图/等待主机选择地图」） | ☐ |

## 2. 出生点分配 / 占用

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 2.1 | 点击空闲出生点 | 自己分配到该出生点：标记变金色外框高亮；「我的配置-出生点」下拉同步；槽位显示「出生N」 | ☐ |
| 2.2 | 点击已被他人占用的出生点 | Toast 提示「出生点 N 已被 xxx 占用」，不分配 | ☐ |
| 2.3 | 再点另一个空闲出生点 | 自己从原出生点移走，新出生点高亮（原标记恢复空闲） | ☐ |
| 2.4 | 通过下拉切换出生点 | 地图预览标记同步高亮新位置（与点击双向联动） | ☐ |
| 2.5 | 加入者 B 改出生点 | A 端预览上 B 的标记位置同步变化（PO 广播） | ☐ |
| 2.6 | A 端看到 B 的出生点 | 标记被 B 玩家颜色填充（圆点变 B 的颜色），编号仍可见 | ☐ |

## 已知限制（本次未实现）

- **TeamStartMapping 队伍映射**：出生点→队伍（2v2/3v3 预设）未接，出生点仅按玩家个人 Start 着色。
- **AI 玩家出生点**：房间内无 AI 槽位，出生点只映射真人玩家。
- **ForceRandomStartLocations**：地图/模式强制随机出生点时，仍允许手动选择（未禁用标记）。
- **FHSH/游戏启动**：出生点配置打包进 spawn.ini 与「开始游戏」真正启动，均在 M3.7 接入。

2. 双客户端：按 §2.5/2.6 验证出生点跨端同步与占用着色。
3. 回归：M3.5 的配置/就绪/聊天/离开流程无回归。
