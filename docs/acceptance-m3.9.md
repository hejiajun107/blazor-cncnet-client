# M3.9 频道指令（邀请/踢/禁言）验收清单

> 范围：大厅聊天输入 `/` 频道指令（`/kick` `/ban` `/mute` `/voice` `/invite` `/help`）+ 玩家右键菜单管理员操作（踢出/封禁/禁言）+ 指令提示浮层。
> 涉及文件：`LobbyService.cs`（`ChannelCommand` 注册表、`ExecuteChannelCommand`、`IsCurrentChannelAdmin`）、`Lobby.razor`（右键菜单管理员项 + 指令提示浮层）、`app.css`（`.cmd-hint`/`.ctx-item.warn`）。
> 状态：实现完成，主工程构建 0 错误；本次改动 0 警告（存量 Core/Domain 工程警告非本次引入）。
> 说明：指令为「本地解析 + 发送 IRC 原始命令」，服务端权限校验为准；客户端 `IsCurrentChannelAdmin` 仅用于 UI 权限提示（非管理员可尝试，频道内给权限不足提示）。

---

## 0. 前置准备（必读）

- 至少 **2 个客户端** A/B 登录同一 CnCNet 大厅进入 `/online/lobby`，需同一频道。
- 权限验证需**频道管理员账号**（该频道玩家列表昵称前带 `@` 的用户）；普通账号可验证权限不足分支。
- `/ban` 按玩家 host 封禁；若真实 IRC 服务端权限不足会由服务端拒绝，客户端仍回「已封禁」本地提示（验收以是否收到服务端反馈为准）。

## 1. 指令解析与输入（单客户端即可）

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 1.1 | 聊天框输入 `/` | 弹出指令提示浮层，列出 KICK/BAN/MUTE/VOICE/INVITE/HELP | ☐ |
| 1.2 | 输入 `/k` | 浮层过滤为 KICK（前缀大小写不敏感） | ☐ |

| 1.5 | 输入 `/foo 123` 回车 | 频道内黄色提示「未知指令 /foo，输入 /help 查看可用指令」 | ☐ |
| 1.6 | 非 `/` 开头的普通消息 | 正常作为聊天消息发送，不进指令分支 | ☐ |

## 2. 指令执行 / 权限校验

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 2.1 | 普通（非管理员）账号执行 `/kick B` | 频道内提示「/KICK 需要频道管理员权限」，不发送 KICK | ☐ |
| 2.2 | 普通账号执行 `/ban B` / `/mute B` | 同上权限不足提示 | ☐ |
| 2.3 | 管理员执行 `/kick 不存在的名字` | 黄色提示「未在当前频道找到玩家 …」，不发送 | ☐ |
| 2.4 | 管理员执行 `/kick 自己` | 黄色提示「不能对自己执行 /kick」 | ☐ |
| 2.5 | 管理员执行 `/kick B`（B 在频道） | 发送 `KICK 频道 B`；服务端处理成功后 B 从频道移除，频道出现系统消息 | ☐ |
| 2.6 | 管理员执行 `/ban B` | 发送 `MODE +b *!*@host` + `KICK`；B 被禁并踢出 | ☐ |
| 2.7 | 管理员执行 `/mute B` | 发送 `MODE 频道 -v B`；B 的 `+` 前缀消失（被禁言） | ☐ |
| 2.8 | 管理员执行 `/voice B` | 发送 `MODE 频道 +v B`；B 恢复 `+` 前缀 | ☐ |
| 2.9 | 管理员执行 `/invite B` | 复用邀请逻辑向广播频道发 CTCP INVITE；频道内提示「已邀请 B 加入游戏」 | ☐ |
| 2.10 | `/kick` `/ban` 无参数 | 黄色提示「用法：/kick <玩家昵称>」等 | ☐ |

## 已知限制

- `/ban` 的 host 在玩家 ident/host 未解析时回退昵称，真实封禁效果取决于 IRC 服务端；权限校验以服务端为准。
- `/mute` `/voice` 通过 `MODE ±v` 实现（原版 IRC 禁言语义），非服务端 `+m` 静音频道，需频道未开启仅 voice 发言模式时语义一致。
- 指令反馈为本地黄色系统消息，不回显给服务器广播。
